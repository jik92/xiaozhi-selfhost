# 小智本地工作台

用 Chrome 连接 ESP32，在一个界面里完成串口配置、固件刷写、设备对话、AI 设置、声纹和 MCP 调试。

**Bun + React + Ant Design**。网关由 TypeScript 实现，不需要部署两套参考项目、MySQL 或 Redis。SQLite 保存设置与记录；本地声纹模型是可选组件。

## 启动

需要 Bun 1.3+、FFmpeg，以及电脑上的 Chrome / Edge。

```sh
# macOS 安装音频转换依赖；已经安装可跳过
brew install ffmpeg

cd xiaozhi-selfhost
bun install --frozen-lockfile
bun run build
bun start
```

打开 **http://localhost:18080**。

开发时运行 `bun dev`：前端 http://localhost:5178，Bun 网关 :18080。开发端口与生产服务不能同时占用。

默认端口：

| 服务 | 端口 / 地址 |
| --- | --- |
| 本机管理界面、OTA、设备 WebSocket | TCP 18080 |
| OTA | `http://电脑局域网IP:18080/xiaozhi/ota/` |
| 设备 WebSocket | `ws://电脑局域网IP:18080/xiaozhi/v1/` |
| 内置 MQTT 3.1.1 设备网关 | TCP 18883 |
| 加密 UDP 音频 | UDP 18884 |

`PORT`、`MQTT_PORT`、`UDP_PORT`、`DATA_DIR`、`FFMPEG_PATH`、`VOICEPRINT_MODEL` 可通过环境变量覆盖。开发模式 Vite 默认代理 :18080；修改 PORT 时同步修改 Vite 代理。

## 让 WHA103 / FoloToy AI Passport 连接本地

Passport 用户在「串口刷写」的「设备板型」选择 **FoloToy AI Passport**。已有小智固件可选「仅配置本地连接」；从其他固件切换请选择「完整固件」，可直接使用内置的 Passport 专用小智 `v2.5.0-folo.1`，无需另行寻找二进制。内置文件加载时校验 SHA-256。详见 [Passport 刷写说明](firmware/README.md#folotoy-ai-passport)。

1. 电脑和小智连接同一个可互访的局域网。「AI 设置」默认自动获取当前局域网 IP，生成配置和下发连接地址时重新读取，优先使用默认路由的物理网卡并排除 VPN、虚拟机网卡。也可切换为手动指定 IP / 主机名，不能填写 `localhost`。设备已保存的旧 OTA IP 不会随电脑网络切换自动更新，需要重新「仅配置本地连接」；长期使用可手动指定设备能解析的稳定主机名。
2. 用 Chrome 打开上面的 **localhost** 地址，在「串口刷写」点击「选择串口」。浏览器的设备选择和串口授权需要本人操作。
3. 推荐选择「保留固件 · 配置本地连接」。选择 WebSocket 或 MQTT+UDP；Wi-Fi 留空会保留已有网络。 macOS 可点击 Wi-Fi 名称旁的「扫描」，选择本机附近的网络（标注频段，优先显示 2.4GHz），也可手动输入；扫描需要 Swift 命令行工具，系统可能要求为启动服务的终端或应用开启定位权限。扫描不会读取密码或切换电脑网络。
4. 点击「写入本地配置并重启」。工具先下载原 NVS 备份，再追加本地连接参数、校验并重启。
5. 收到设备真实的 OTA 请求后才标记为接入成功。WebSocket 通常在唤醒设备后才建立；去「设备与对话」查看状态。

配置过程写入 `wifi.ota_url`、WebSocket 与 MQTT 参数；保留其他 NVS 条目和非 NVS 分区。设备令牌在本机生成，通过本地 OTA 下发，无需小智官方账号。切换协议后需要重新配置或让设备重新读取 OTA。

**当前串口自动配置适配 WHA103 和 FoloToy AI Passport / ESP32-C3、ESP-IDF NVS v2、0x8000 分区表与兼容小智固件的 `wifi.ssid/password` 配置。** 不是所有 ESP32 板子的通用配网器。加密 NVS、损坏分区、空间不足、其他芯片都会拒绝写入；不会猜测引脚或擦除整片 Flash。

已有可用固件也可不使用串口：先在「设备与对话」登记 MAC，再在小智配网页面高级选项填入本地 OTA 地址并重启。

## 完整固件刷写

界面支持上传板型匹配、从 `0x0` 开始的完整合并 `.bin`。刷写前验证芯片 ID、容量和 NVS 分区兼容性，刷写时使用 MD5 校验，最后回读配置。自动备份的是 NVS，**不是整片 Flash**；首次更换厂商固件前请单独备份完整 Flash。

本项目不附带假定适配 WHA103 的通用固件。已经检查的官方上游没有 WHA103 板型源码，不能安全地把其他 C3 固件当成它的驱动。现有设备可以先使用「保留固件」模式。完整编译需要厂商板级源码或确认过的引脚定义，见 [firmware/README.md](firmware/README.md)。

整个操作通过浏览器 `esptool-js` / Web Serial 完成；Bun 后端不占用串口。测试和启动项目不会自动刷写硬件。

## AI 对话

在「AI 设置」中保存并测试：

- 大模型：OpenAI 兼容 `/chat/completions`，可配置 UAT 网关或自己的模型服务。
- 语音识别：Qwen ASR 多模态接口，或 OpenAI/Whisper 兼容 `/audio/transcriptions`。
- 语音合成：Edge TTS，或 OpenAI 兼容 `/audio/speech`。FFmpeg 转为 24kHz 单声道 PCM，再按设备协商帧长编码 Opus。
- 本地断句：RMS 音量检测、可配置静音时间。支持 `manual` 输入结束和自动断句；这不是神经网络 VAD，也没有实现服务器 AEC。
- 唤醒回复：设备通过 `listen/detect.text` 上报固件识别到的唤醒词后，网关直接播报「设备唤醒后的回复」（默认“我在，请说。”），留空关闭。按钮进入聆听不会触发此回复。
- 语音前缀过滤：在「AI 设置 → 唤醒与语音输入」填写，例如 `小智`。每轮识别结果须以此前缀开头，网关移除前缀及后续标点，再将指令交给模型；不匹配或仅说前缀时不回复。留空关闭前缀限制，网页文字对话不受影响。此功能依赖设备已上传音频，不改变固件的待机唤醒词。
- 对话保留最近若干轮上下文；模型可调用已配置的远程和设备 MCP 工具。每轮最多执行四轮工具调用。

API Key 保存在仅当前用户可读的 `data/xiaozhi.sqlite` 中，管理 API 只返回掩码。也可用 `AI_API_KEY`、`AI_MODEL`、`ASR_API_KEY` 设置初始值；已有的数据库设置优先。

「自建网关」不等于完全离线。默认 Edge TTS 会访问微软服务，云模型和云 ASR 会访问配置的服务商。要全内网运行，应为这些位置填写对应的内网兼容服务。

## 角色与语音

在「角色与语音」选择预设或新增角色，编辑名称、角色介绍及音色，保存后下一轮对话生效。内置“来自台湾的知心朋友”完整人设，支持普通话与台湾普通话音色预设；也可填写服务商支持的音色 ID。Edge TTS 与兼容 TTS 分别保存角色音色，切换服务时互不覆盖。选择“默认助手”恢复使用「AI 设置」中的角色设定和默认音色。角色最多 20 个，支持编辑和删除。

- 识别速度：慢 / 标准 / 快，分别使用基础静音断句时间的 1.5 / 1 / 0.5 倍（限制在 300–5000ms）。只调整自动断句等待，不改变 ASR 模型的处理耗时；手动结束录音由设备控制。
- 回复速度：慢 / 标准 / 快，约为 0.8 / 1 / 1.2 倍速。
- 回复音调：低 / 标准 / 高。Edge TTS 使用原生语速与音调参数；兼容 TTS 使用 FFmpeg 调整音频，不要求服务商额外支持音调参数。

语速与音调设置用于语音回复、文字播报和「保存并试听」，不改变上传音频的原始音色。首次使用和旧配置均沿用默认助手与标准速度、标准音调，不影响已有对话及前缀过滤设置。

## AI 定时任务

在「AI 设置」后的「AI 定时任务」新增任务，选择设备并填写“发给小欧的话”。任务使用当前角色和同一套 AI / MCP 工具流程，以用户消息触发：

- 间隔时间：每隔指定秒数、分钟数或小时数执行。
- 定时触发：每天指定时间，或指定日期时间仅执行一次。时间均按北京时间（UTC+8）。
- 延迟一次：保存或重新启用后开始倒计时，执行一次即关闭。

支持暂停、编辑、立即执行、停止和删除，并显示下次时间、最近结果与播报状态。“立即执行”会结束目标设备的待机聆听并尝试播报，不打断正在处理或播放的其他对话；同时会消耗延迟或指定日期的一次性任务；间隔与每日任务保留原计划。离线或设备忙时仍执行 AI 任务并保存结果，不远程唤醒设备、不插播或排队补播；设备在线空闲时使用当前音色播报。任务和结果保存在 SQLite；运行需要本机服务保持启动。

同一任务不重叠，同时最多执行 3 个任务，每次最多运行 5 分钟。服务恢复后，已到期且尚未执行的任务触发一次，不补跑每一个错过的间隔。运行中被重启打断的任务标记为失败；一次性任务不会自动重放，避免重复执行有副作用的命令。

## 本地内置 MCP 工具

「MCP」默认包含不能删除的“本地内置工具”，无需配置额外服务。点击“读取工具”即可调试，也会直接提供给模型和定时任务调用：

- `get_current_time`：获取日期、时间和星期，支持 IANA 时区，默认 `Asia/Shanghai`。
- `websearch`：通过 Bing RSS 搜索网页，返回标题、链接和摘要，无需密钥；需要网络，搜索源不可用时明确返回错误。
- `bash`：在本机执行 Bash 命令，默认工作目录为项目目录，可指定目录；默认超时 20 秒，可设 1–60 秒，合计输出上限 16KB。返回退出码、标准输出、标准错误、是否超时或截断。取消或超时会终止进程组。

Bash 以网关进程的当前用户权限执行；这些工具与管理接口一样，仅通过本机管理页面或已配对设备的 AI 对话使用。返回内容会使用现有的密钥脱敏规则。

## 本地声纹

```sh
bun run setup:voiceprint
```

从 sherpa-onnx 官方 Release 下载约 28MB 的 3D-Speaker CAMPPlus ONNX 模型到 `data/models/speaker.onnx`。`sherpa-onnx-node` 是可选平台依赖，当前实现已在 macOS arm64 + Bun 下验证。也可以导入已有模型：

```sh
bun run setup:voiceprint /绝对路径/兼容的声纹模型.onnx
```

在「声纹识别」选择「本地模型」，开启识别，添加说话人并上传至少 3 秒清晰录音。独立 Worker 提取 192 维特征，SQLite 保存特征，使用余弦相似度匹配已登记说话人；原始样本音频不会保存到数据库。

也支持外部兼容服务，Base URL 不含接口路径：

- `POST /voiceprint/register`：Bearer 认证，multipart `speaker_id` + `file`（16kHz 单声道 WAV）。
- `POST /voiceprint/identify`：Bearer 认证，multipart `speaker_ids`（逗号分隔）+ `file`，返回 `{ "speaker_id": "...", "score": 0.8 }`。

外部接口格式参考 Python 项目并增加登记约定；如果已有服务格式不同，需要对应适配，不会自动假定兼容 Go 项目的所有声纹接口。删除本地说话人只移除本地记录，不删除外部服务中的档案。

## MCP 与主动音频

「设备与对话」默认开启“网页自动播报”，使用设备本次实际生成的音频，同步在浏览器播放，无需再次合成。开关偏好保存在当前浏览器。首次自动播放被浏览器拦截时，点击页面上的“点击播放”开启声音；后续回复会按顺序播放。支持“停止网页声音”，关闭开关、切换设备或离开页面会清空播放队列；设备打断时也会停止对应语音。只播放进入页面后的新音频，不重播历史文字。音频在服务端内存中临时保留 2 分钟、最多 24MB，不写入数据库或磁盘。

新增的用户语音消息支持点击“播放原声”，在网页回放该条消息对应的设备输入录音，不调用 TTS、不自动播放。关闭“网页自动播报”后仍可手动回放；再次点击或“停止网页声音”可以停止。原始录音与用户消息关联保存在本机 SQLite，重启后仍可回放，最多保留最近 200 条且总容量不超过 64MB，超出时清理旧录音并保留文字。文字输入、旧版未保存的录音和已清理录音的消息显示“无录音”。

欧尼博 registry 的独立 HTTP 适配、启动和身份配置见 [integrations/moment-factory/README.md](integrations/moment-factory/README.md)。适配代码在本项目内，不需要修改 registry 源码。

「MCP 工具」支持 Streamable HTTP 和旧版 SSE，可设置 Bearer Token、发现工具、查看参数并执行调用。设备端 MCP 走小智协议的 `type: mcp`，自动初始化并读取工具，支持本地调试和模型调用。

「设备与对话」提供三种下发方式：

- 发送对话：文字 → 模型 → TTS → 设备。
- 直接播报：文字 → TTS → 设备。
- 上传音频：WAV/MP3 等 → FFmpeg → Opus → 设备。

支持停止、打断、设备重连清理，音频按帧长节奏发送。**设备必须在线且音频通道已经打开**；MQTT+UDP 还需要设备先发送音频以建立 UDP 回程地址。不会把离线下发或尚未建立 UDP 通道标为播放成功。当前不实现离线队列或远程唤醒。

## 钉钉消息通知（Stream）

MCP 后的「钉钉消息通知」菜单支持应用机器人 Stream 模式，参考 Air780E 控制台的长连接接入方式，使用钉钉官方 [Stream 协议](https://opensource.dingtalk.com/developerpedia/docs/learn/stream/protocol/)。无需公网回调地址、Webhook 或加签密钥。

1. 在钉钉开发者后台创建应用机器人，配置接收模式为 Stream，发布应用并确认使用范围包含发送人。
2. 填写该应用的 Client ID / AppKey、Client Secret / AppSecret，选择播报设备并启用，保存后等状态显示「Stream 已连接」。密钥保存在本机受限 SQLite 文件中，设置接口仅返回是否已保存；留空保留旧密钥。
3. 与机器人单聊发送文本，或在群里 @ 机器人发送文本。支持限定会话 / 群 ID 和发送人 ID；留空允许机器人可收到的全部来源，可从页面最近消息来源取得 ID。这不是对任意钉钉聊天消息的监听。
4. 收到消息后，使用「角色与语音」当前角色和音色生成简短口语播报，走现有 TTS / Opus 音频链路。通知仅作为外部数据转述，不开放 MCP 工具调用。页面显示最近通知、排队、失败和音频发送状态，不向钉钉回复消息。

目标设备必须保持连接，Passport 选择 MQTT 后可通过常驻控制连接接收 `notify` 并下载 Ogg Opus 音频，待机播报不需要按 OK 或开启 UDP 通道。其他 MQTT 设备仍需音频通道就绪。无法远程唤醒断线或休眠设备；忙碌、聆听、离线或音频通道未就绪时等待，每条消息最多保留 10 分钟，最多排队 50 条。修改设置会取消待播队列和正在处理的通知；已下载到设备的音频可能继续播放。Stream 自动重连，消息 ID 持久去重；已开始播报的消息在服务重启后标记结果未知，不自动重播。记录「音频已发送」表示服务器发送完成，不能确认扬声器听感。

`GET /api/dingtalk` 查看脱敏配置、连接状态和最近通知；`PUT /api/dingtalk` 保存设置并重建连接，均沿用仅限 localhost 的管理访问控制。自动测试使用模拟 Stream 帧和 AI 上游，验证回调到实际 WebSocket/Opus 音频；真实应用连通性及设备听感需填写自己的凭据后验证。

## Passport 待机主动播报

已内置的 Passport 小智 `v2.5.0-folo.1` 支持 [异步通知协议](https://github.com/FoloToy/folo-ai-passport-xiaozhi/blob/v2.5.0-folo.1/docs/notify.md)，无需重新编译固件。在「串口刷写」选择 **FoloToy AI Passport → 仅配置本地连接 → MQTT + UDP**，写入配置并重启。设备连接 MQTT 后，定时任务和钉钉通知自动使用此通道；不需要先按 OK 开启对话，也不依赖 UDP 音频通道。WebSocket 模式仍需保持对话连接。

服务端使用当前角色和音色生成音频，转成单声道 Ogg Opus，通过 MQTT `notify` 下发临时下载地址。设备在 Idle 状态自行下载并播放，结束后返回待机，不打开麦克风。真正断网、断电或深睡的设备仍无法被网络通知唤起。目标设备需能访问本机公布的局域网 HTTP 地址和 MQTT 端口。

通知音频仅缓存在内存，使用 256 位随机地址、2 分钟有效期、24 MB / 20 条容量上限，并绑定当前设备会话。取消、断线或流程结束后撤销地址；下载接口只允许 GET，返回 `audio/ogg` 且禁止缓存，不开放管理 API 或浏览器音频接口。服务端等待设备请求音频（最多 20 秒）；未请求记为失败，已请求显示「通知已下发」，不冒充播放完成回执。固件可能忽略繁忙时收到的通知，已下载音频也不保证能被服务端取消；后端在预计播放期间保留设备占用，用户在实物上唤醒可打断播报。

测试覆盖真实 MQTT 连接、没有 hello / UDP 通道时的定时任务及钉钉通知、Ogg Opus 下载与解码、取消、下载超时和失效地址。设备是否实际发声需在切换协议后验证。

## 协议实现与范围

WebSocket 支持小智 v1 原始 Opus、v2 16 字节头、v3 4 字节头。MQTT 3.1.1 提供设备连接、用户名/密码认证、QoS 0/1 上行、订阅和心跳；设备主题按身份隔离。它是专用设备网关，不是完整的通用 MQTT Broker，不提供 QoS 2、持久会话或 retained 消息。

MQTT 控制配合 16 字节包头、AES-128-CTR UDP 音频，校验长度和序列号并丢弃重放包，匹配固件端协议。该协议本身没有认证加密；本项目面向可信局域网，不把这些端口直接发布到公网。管理 API 和页面限制本机访问。

OTA 只返回当前版本和本地连接参数，不自动升级固件；刷写完整固件通过浏览器执行。没有实现视觉、知识库、声音克隆或完整多租户管理。

## 检查

```sh
bun run check
bun test
bun run build
```

集成测试使用真实 TCP/WebSocket/UDP 连接和 Opus/FFmpeg，AI 使用本地测试替身，覆盖语音上行到模型与音频下行、主动播报、MCP HTTP 调用、OTA 认证与密钥遮蔽、断线清理。NVS 测试覆盖 CRC、覆盖更新、页切换、损坏数据和空间不足。测试不会访问串口或使用真实 API Key。

浏览器串口授权、实际 Flash 写入以及设备麦克风/喇叭的物理表现，需要真实设备验收；模拟设备测试不能替代这些检查。

## 文件结构

```text
src/                 React 控制台与浏览器串口工具
server/              Bun 网关、会话、AI、MCP、本地声纹 Worker
shared/              数据契约与 ESP-IDF NVS 编解码
tests/               单元测试与网络集成测试
scripts/             开发启动、模型安装
integrations/        独立 MCP 接入适配（欧尼博 HTTP Bridge）
firmware/            固件适配说明，不包含厂商二进制
data/                SQLite、声纹模型、运行数据（Git 忽略）
```

备份 `data/` 可保留设置、设备凭据、声纹特征和聊天记录。不要把数据库、NVS 备份、厂商完整 Flash 或密钥上传到公共仓库。
